# Runtime recovery report (reported on 0.1.0-alpha.1206)

Branch `arimendelow-runtime-recovery-fixes`. Status: see the PR; a release is claimed only once it is published and verified (this document is written before merge and states no release).

## What was found and changed

1. **Bundle sync, `git: 'remote-https' is not a git command`.** The ms-desk shim at `~/.local/bin/git` execs the first non-shim `git` on PATH, which on the mini is the Copilot app's bundled git (`~/Library/Caches/github-copilot-git-<ver>/bin/git`). That build is relocatable: without the app's `GIT_EXEC_PATH` its exec path is `//libexec/git-core`, so `git-remote-https` is not found. A daemon that inherits the app's PATH but not `GIT_EXEC_PATH` (or one pointing at a deleted versioned cache) fails every fetch and push; the same mechanism explains `~/code/teams-microsoft_tandem`. Reproduced locally with `git ls-remote http://127.0.0.1:1/x.git`. Fix: `src/heart/git-binary.ts` (healthy-git selection and env sanitising), used by `runGit`/`runGitAsync` in `src/heart/sync.ts`. The shim and the app's environment are outside this repo.
2. **Laptop unreachable / week-old presence.** Per the assigner's scope correction, SSH/Tailscale repair is dropped. Peer presence travels only through bundle sync (`presence/<machineId>.json`, every 15 min), so #1 is the cause of the week-old data. Fix: `isStaleSeenAt` (`src/heart/daemon/presence.ts`) and STALE markers in `src/mind/where-am-i.ts` and `src/heart/daemon/presence-roster.ts`.
3. **Stale where-work-runs view.** Passive data that exposes what runs where: each machine's `presence/<machineId>.json` in the bundle (`PeerRecord` in [`presence.ts`](../src/heart/daemon/presence.ts): `owns` senses, `failover`, `appSessions` counts, `seenAt`), plus the roster/owners in `agent.json`, read by [`where-am-i.ts`](../src/mind/where-am-i.ts) and `ouro presence status` ([`presence-roster.ts`](../src/heart/daemon/presence-roster.ts)). That data does not include which coordinator chat is doing which task; only sense ownership and Copilot-app session counts per machine are published. Same stale cause as #2; the STALE marker now names the source (the bundle record, delivered only by git sync) and the commands to check (`ouro presence status`, `ouro status` sync health).
4. **Teams repeating dead proactive messages.** Path traced from code: every delivered proactive send is written into the conversation's session history as `[you sent this via a proactive message] <text>` by `recordOutboundInSession` ([`outbound-record.ts`](../src/mind/outbound-record.ts)), persisted, and replayed to the model on every later turn of that session. `appendSyntheticAssistantMessage` ([`context.ts`](../src/mind/context.ts)) only avoids a second copy when the `deliveryId` matches one already in the session. The pending-file drain ([`teams.ts` `drainAndSendPendingTeams`](../src/senses/teams.ts)) sent with a random `proactive:<uuid>` id, so any replay of the same pending file (unlink failed, restored checkout, a file that stayed queued while Teams was down) wrote another copy into context; the forwarded outbox path already used a stable `off-turn:` id. Fixes: stable per-file `pending:<hash>` delivery id (so a replay is recorded once), plus 6 h expiry on the pending files and on `presence/outbox` entries so dead messages are not sent late. Not changed: copies already persisted in a session's history stay there. Which replay actually occurred on the mini is not observable from here.
