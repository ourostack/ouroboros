- `coding_spawn` is now the one way an agent starts a coding agent, and it opens it in Orca by default: a repo checkout gets its own Orca worktree, an existing Orca worktree gets a new agent tab, and either way the agent shows in Orca's sidebar with its terminal. `coding_status`, `coding_tail`, `coding_send_input` and `coding_kill` work on it like any other session: status comes from Orca's agent state, tail from the terminal's screen, input is typed into the terminal, and kill closes the tab but keeps the worktree.
- `coding_spawn` takes `backend` (`orca`, `local` or `workbench`) to choose somewhere else for one job. An agent's default is `coding.backend` in agent.json, `orca` when unset; an unknown value is refused, not replaced with another. `local` is the old headless claude or codex child process. Workbench now gets picked as a backend this way instead of through the `features.workbenchCoding` runtime flag, which is gone.
- An Orca session is not marked finished on one missed check: its terminal has to be missing from three refreshes in a row, and it counts as completed only if Orca last saw the agent done (Orca's `done` alone means the agent finished a turn and waits for more). After Orca restarts, a session finds its terminal again by its tab and pane, never by taking another session's terminal. A checkout Orca doesn't know yet is registered with Orca before the worktree is made. If Orca opens the agent but cannot deliver its prompt, the tab is closed and the spawn fails with the worktree's path.
