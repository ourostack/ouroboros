Whether the Butler takes delegated commands and failure reports from other agents is now set in its product registration. Before, the A2A sense and the A2A server wiring each checked the Butler's name. On the Butler's image nothing changes: peers the operator granted can still send delegated commands, each one is still announced in the owner's own Telegram chat before it runs, and escalation peers can still file failure reports that are confirmed to the owner once the fix is live. The A2A sense now logs `senses.a2a_delegation_wired` when it turns delegation on. Agents with no product never get either, and that now includes a `butler` or `sanctuary` bundle run outside the Butler's image, which got both before. A notice that fails now also logs `daemon.product_hook_error`, and the command is still refused.
