Blind interviews: the U image. `deploy/eval/u` builds the three project templates and the checking tools that product U's arms run against, and an image that adds them to the eval agent image. Each template is the same React project with one kit installed as `@kit/ui`: Ouro UI and shadcn/ui are packaged from their component sources, and MUI from its own build. Every brand word is rewritten to a neutral one, node_modules included, and a scan then finds none left.

The tools type-check the component, scan it with axe, and run the hidden test. The component runs in jsdom in a separate process under Node's permission model, which can't read the hidden test or write files, and its imports resolve only inside its project. The page's driver only renders and presses, and the page's process judges nothing. At each step it reads the live DOM from jsdom's own node tree into plain data and sends it to the checking tools' own process, where no page code runs. A getter or proxy the page planted on jsdom's objects ends the run as tampered. The tools rebuild each snapshot with DOM calls as a script-free copy that keeps every element where the page had it, head included, with its attributes, text, inline style and computed display and visibility but not the page's stylesheets, and give every verdict, axe's included, from that copy. The runner also closes the known ways out of jsdom to itself: it refuses code from strings, takes away its Function constructors and stack-trace hooks, gives frames no window, and freezes its built-ins and the jsdom classes the page can reach. This is hardening, not proof, so transcripts are kept. As a safeguard, a static scan flags any component whose source names a way out of the page, and a flagged run counts only when the hidden test passes again in a fresh process. The hidden test follows the registered rule closely. The confirm must be a control the first press brought in, or one in a dialog, or one that changed to ask, and never one naming 189 alone; a name starting with remove or delete always confirms and goes first. It is pressed a random 0.5 to 1.5 s after it appears, the first press holds only if onRemove hasn't run by then, and only calls after the confirm press count. Then a holding check renders the component afresh, presses remove without confirming, and fails the run on any onRemove call within 5 s. The status must not be hidden, aria-hidden or inert, and the confirm must change it so that a sentence says removed or done, with no negation or future before the claim, no question and no failure. A status that is only transparent or clipped still counts, as it would for a screen reader. Each kit has a reference solution that must pass the full grade, and a self-test checks the grader against passing and failing components, including ones that try to escape or forge a grade. The scripts that ran each kit's own tests after the rewrite, and the same tests on the unrewritten pins, are kept with the build, and their results are in `deploy/eval/u/results`. MUI's tests all pass once its own test utilities get the same replacements. Ouro UI keeps 6 failures whose expected values come from the brand text itself, recorded as fidelity notes. shadcn/ui's registry has no tests.

U's guest now runs in the U image by name (`image: "u"`). CI's eval sandbox job builds a stand-in for it: the agent image, the real checking tools and a stub kit (`ouro-eval-u-stub-ci:local`, which never serves a session). It then runs a scripted U conversation for each arm in the read-only container, and checks that a component which tries to print its own grade stays contained and fails.
