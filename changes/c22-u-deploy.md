Blind interviews: the U image. `deploy/eval/u` builds the three project templates and the checking tools that product U's arms run against, and an image that adds them to the eval agent image. Each template is the same React project with one kit installed as `@kit/ui`: Ouro UI and shadcn/ui are packaged from their component sources, and MUI from its own build. Every brand word is rewritten to a neutral one, node_modules included, and a scan then finds none left.

The tools type-check the component, scan it with axe, and run the hidden test. The component runs in jsdom in a separate process under Node's permission model, which can't read the hidden test or write files, and its imports resolve only inside its project. The page's driver only renders and presses. Every verdict, axe's included, is computed outside the page: the runner copies the live DOM from jsdom's own node tree, with each element's attributes, text, and computed display and visibility, into a script-free document and judges that copy. The runner also closes the known ways out of jsdom to itself: it refuses code from strings, takes away its Function constructors and stack-trace hooks, gives frames no window, and freezes its built-ins and the jsdom classes the copies share. A result counts only when it's signed with a key the page never sees. This is hardening, not proof, so transcripts are kept. As a safeguard, a static scan flags any component whose source names a way out of the page, and a flagged run counts only when the hidden test passes again in a fresh process. The hidden test follows the registered rule closely. The confirm must be a control the first press brought in, or one that changed to ask, and never 189's. The status must not be hidden, aria-hidden or inert, and the confirm must change it so that one of its sentences says removed or done without negating it. A status that is only transparent or clipped still counts, as it would for a screen reader. Each kit has a reference solution that must pass the full grade, and a self-test checks the grader against passing and failing components, including ones that try to escape or forge a grade. The scripts that ran each kit's own tests after the rewrite, and the same tests on the unrewritten pins, are kept with the build, and their results are in `deploy/eval/u/results`. MUI's tests all pass once its own test utilities get the same replacements. Ouro UI keeps 6 failures whose expected values come from the brand text itself, recorded as fidelity notes. shadcn/ui's registry has no tests.

U's guest now runs in the U image by name (`image: "u"`). CI's eval sandbox job builds a stand-in for it: the agent image, the real checking tools and a stub kit (`ouro-eval-u-stub-ci:local`, which never serves a session). It then runs a scripted U conversation for each arm in the read-only container, and checks that a component which tries to print its own grade stays contained and fails.
