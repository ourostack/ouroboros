- Phone calls on the OpenAI Realtime and SIP engines now record an outcome for each thing the caller says, as cascade calls already did. The earlier note said these engines were "not covered yet". Local audio rooms, which also run on the Realtime engine, are still not recorded. Each utterance is recorded once its transcript arrives, before a reply is asked for. The next reply the caller asked for answers everything they said since the last one. A greeting or a holding phrase answers nobody, and a reply that only called a tool hands what it answers on to the next one.
- On those engines a reply counts as answered only once some of its audio played. On a Media Stream that means Twilio reported it played. On SIP it means OpenAI reported it started streaming the reply's audio to the caller. A reply's speech is noted before its audio goes out. A tool that may message a person is noted once its own checks pass, just before it runs, so a tool they refuse is not noted.
- A reply whose audio was cleared before any played is recorded as failed, with the reason: the call ended, the caller talked over it, or a tool's audio took its place. If OpenAI keeps sending that reply's audio and some of it plays, it counts as answered. The call's opening audio plays after whatever is already playing, so it no longer stops a reply from counting. When the call hangs up through `voice_end_call` without speaking to what the caller said, that is recorded as silent. So is a Realtime or SIP outbound call answered by a voicemail or fax machine. Live audio is never replayed.
- Each utterance record now names the process and bridge that made it. Once a bridge is listening, it records as failed only leftovers from a bridge that closed, a process that stopped, or an older build. It does the same for its own calls if it shuts down. Records of a bridge still open, in this process or another running one, are left for a later check, so a second bridge on another port with the same folder no longer fails a running call. Nothing in the daemon closes a voice bridge today, so in practice what a stopped process left is recorded as failed when the voice sense next starts.
