- iMessages sent while BlueBubbles or the Mac was down now reach the agent after recovery. iMessage delivers the messages it held minutes after BlueBubbles answers again, dated when they were sent, and BlueBubbles sends no webhook for them, so one catch-up at the moment of recovery missed them. For 30 minutes after an outage every catch-up now keeps reaching back 24 hours, even when the recovery pass itself is cut short by a restart, and outage catch-ups are logged.
- A habit whose run was lost before it finished (a crash or restart mid-run) no longer stops for good. Every later firing reused the lost run's occurrence and was refused as its duplicate, which stopped Slugger's heartbeat for 14 hours. A habit a whole interval past due now gets a new occurrence, and the overdue habit and each refused duplicate are logged as warnings.
- launchd now runs interval habits on schedule. The scheduler reloaded every habit's launch agent on its 5-minute pass, which restarted the launch agent's 30-minute clock each time, so launchd never ran the heartbeat. A loaded launch agent whose plist has not changed is now left alone, and a launchd or cron firing for a habit that already ran within its cadence is skipped, so one interval never runs it twice.
- Self-update no longer rolls back a release because one sense is down. `ouro up` refuses to finish while any sense is unhealthy, so a BlueBubbles outage rolled back and blacklisted every release that arrived during it. `ouro up` now exits with code 3 when only that health check refused. The updater accepts such a release only when the daemon answers on it with its health checks reported and its workers listed, and everything still wrong was already wrong, at the same severity, before the update. Any other `ouro up` failure still rolls back, and a failed `ouro up` reports its reason instead of an empty one.
