- The Butler's host upgrade tells the bundle migration which Butler name the new image runs (`--butler-name`), so the bundle's own files (agent.json, the replay-client provisioning record, recent attachments, skills and HOUSE.md) name the container path that image mounts.
- An await filed from an external event still resolves after the Butler's events folder moves to its other name, in either direction.
- When the Butler starts and finds events saved under its other name, it merges them into its own folder even when both folders exist. It combines the privileged spool's replay manifests first, so no accepted envelope is accepted twice. A record both folders have keeps the running Butler's copy, and the other copy moves to `external-events/.adoption-conflicts/<other name>/<time>/`, with a warning; nothing is deleted and the start goes on. Only a move that fails stops the daemon from starting, with guidance naming the container and Unraid host paths. An other-name entry that is a symlink is left alone, with a warning.
- An upgrade that would change the Butler's name is refused, before anything is paused or changed, unless the running release can take a rollback across the rename. Ship a release from after this change with the name unchanged first, then the release that renames it.
- A held upgrade (`--hold-commit`) now says that a rollback puts the migrated bundle files back as they were before the migrate, so edits made to them during the hold are lost.
- The health acceptance probe runs as the Butler whose bundle is on disk, and the privileged spool scan files envelopes under the Butler the daemon start set, so neither recreates the other name's events folder after the rename.
