`coding_spawn` on Orca now checks that the coding agent actually took its task. It no longer trusts Orca's "handed to terminal" receipt, which only means the keystrokes were sent. If no agent shows up in the tab within 90 seconds, Ouro closes the tab and launches once more in the same worktree. If that also fails, the spawn fails and says what the terminal showed, for example `zsh: command not found: laude`.

When the agent opens but stops at a question before taking its task, such as Codex's "Hooks need review" or a folder-trust prompt, Ouro no longer reports it as working. The session is marked as waiting for input, its tab stays open, and its checkpoint shows the question and says a person has to answer it there. Ouro does not answer trust questions itself. Once someone answers, the agent takes the task and the session goes back to running.
