- The agent can no longer write something that passes for a letter into the person's letters chat (the one-to-one iMessage chat with their answering handle). The BlueBubbles client refuses agent text there that folds to a letter code such as `L7`, `Ｌ８` or `letter 3`, or to `Options (from Ouro):`, before anything reaches the server. It does the same for an attachment's file name, and for an edit that would turn any message into a letter. Only Ouro's own rendered letters carry the mark that lets them through. Ordinary text, other chats and group chats are unaffected.
- The letters chat is found however a send names it: by its chat GUID in any field, by the GUID's own one-to-one shape even when a display name marks the chat as a group, and by the handle frozen on any letter still open, after the person's handle has changed. If `answering.json` doesn't read, coded text is refused in every one-to-one chat rather than let through.
- When the letters chat refuses the agent's text, the agent hears why. A refused reply ends that turn without a retry, and a note in the agent's private runtime says the person hasn't heard back. `send_message` and `surface` return the refusal's own words. A caption is checked before its image or file goes, so a refusal never leaves half a message.
