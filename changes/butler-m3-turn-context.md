The house runtime the Butler's tools read on each turn (its Unraid reads, downloads and media clients, and the answer checks it opts in to) now comes from the Butler's product registration, so private turns, A2A turns and Telegram no longer build it themselves. On the Butler's image every turn gets the same context as before: a turn for one of its own house or Usenet events still fails when the house config is missing, and any other private turn still runs without it. That fallback is now logged as `daemon.product_hook_error` at warn level instead of `senses.sanctuary_tool_context_unavailable`, and a failed build on an A2A turn or a Telegram start logs the same event at error level before the turn or start fails as it did before. The Telegram sense now gets that context when it starts, before it builds its app, so a missing house config stops the sense's start as before. Agents no product runs never get the Butler's house runtime, even for a `sanctuary-*` event.
