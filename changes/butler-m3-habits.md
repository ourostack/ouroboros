The Butler's scheduled house check (`sanctuary-health`) now comes from the Butler's product registration, so the daemon no longer calls Butler code to run it. On the Butler's image it behaves as before. Only Supercronic can fire the house check on its cron schedule, and a cron poke without that proof is still refused, now with the message `cron habit 'sanctuary-health' requires authenticated Supercronic provenance`. The proof itself, scheduler attestation, is now part of the harness, and its one-use claims are kept under `state/scheduler/fire-claims` instead of `state/scheduler/sanctuary-fire-claims`. Agents no product runs are unaffected: their habits go the usual route.
