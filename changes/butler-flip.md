- The Butler image now runs the Butler as `butler` instead of `sanctuary`. Its ENTRYPOINT and healthcheck say `--package-managed-agent butler`, and inside the container its bundle is `/home/ouro/AgentBundles/butler.ouro`, its operator trust `/etc/ouro/trust/butler` and its health habit's crontab `/home/ouro/.ouro-cli/scheduler/butler.crontab`. Nothing moves on the host: the bundle stays in `/mnt/user/appdata/ouro-butler/agent/sanctuary.ouro`, the trust folder in `/mnt/user/appdata/ouro-butler/trust/sanctuary`, and the machine id stays `sanctuary`. The upgrade mounts the same host folders under the new name and tells the bundle migration `--butler-name butler`. A rollback to an older image mounts them under `sanctuary` again.
- The DockerMan template's bundle and trust Targets name `butler`; their Defaults are still the host's `sanctuary` folders, and the upgrade still moves the Targets to whichever name the image runs.
- A fresh install reads the Butler's name from the image it pulled, seeds the bundle under that name and keeps the machine id `sanctuary`.
- The Unit 16 acceptance tools follow the name: the launcher reads it from the image, the host broker and target audit accept either name's mounts and control socket, and the in-container adapter, scenarios and health probe use the bundle that is on disk.
- The runbook and the GitHub backup guide name the `butler` container paths, and say to put `sanctuary` in their place on an older image.
