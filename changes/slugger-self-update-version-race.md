- The unattended updater no longer rolls back a healthy daemon because a newer release came up while it waited. On 2026-11-27 a pass installed 0.1.0-alpha.1710, the `ouro up` it runs to restart the daemon found and installed 0.1.0-alpha.1711, and the pass then read the daemon answering on 1711 as a failure: it marked 1710 failed, pinned 0.1.0-alpha.1704 and stopped the healthy 1711 daemon. Now a daemon that answers on the target or any newer release counts as healthy, and the restart is judged by health rather than by an exact version match.
- `ouro up` no longer installs a release while a self-update pass is running, including the `ouro up` that pass runs itself: both now take the same update lock, and the one that finds it held leaves updating to the holder. A lock left by a crashed process is taken over once its owner is gone or it is older than two hours, so a crash never stops updates.
- A rollback no longer stops a daemon that still answers on a version other than the failed one. It reactivates and pins the previous version and leaves that daemon running. A pass also leaves alone a daemon running a newer release than the active one, unless that release already failed on this machine.
