- When a release's verify-npm step still sees the `latest` tag behind the version it published after its 10-minute wait, it now prints read-only diagnostics from several registry read paths (npm view dist-tags, `npm dist-tag ls`, the registry's dist-tags endpoint with its cache headers, and recent publish times) before failing. The wait length and the failure are unchanged; the diagnostics record what each path returned, not a cause.
