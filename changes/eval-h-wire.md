The H interview guest has a model endpoint for the other harnesses: a Responses-API server on the agent container's loopback that codex is pointed at as a custom provider. Each request is turned into the harness's own request and sent through the host's runtime, so the host still rewrites, scans, gates and meters every call. The trace comes from the same traffic, so the case's assertions read each call with the output the harness sent back for it. The case's earlier conversation goes before the harness's first user message. Anything the server can't carry faithfully (another tool type, a custom tool call, an image) is refused by name and never sent. Every failure is answered with a 400, which codex doesn't retry, so no call is metered twice, and every request gets an answer.
