- The daemon can now record a person's answer to a letter from their own iMessage. Given only a message's GUID, it reads that message from the agent's BlueBubbles server and records the answer when every check holds on the server's own fields. The text must be exactly the letter's code and an option number, such as `L7 2`, with an optional note after a dash. It must come from the letter's answering handle in that handle's one-to-one iMessage chat, not by SMS and not as a threaded reply, edit or retraction, and it must be sent after the letter was delivered. The GUID must not have answered before; a ledger in `state/letters/answered-guids.jsonl` keeps replays and recovery passes from answering twice. Anything else records nothing. The daemon asks only a server on the same Mac, over authenticated TLS or on the tailnet, because the fetch carries the server password. Each answer records whether iMessage runs under its own macOS account (`separate`) or not (`shared-apple-id`). The chat ingress that sends these GUIDs comes in the next change.
