The Butler's tool rules now come from its product registration, not from core. The product says the Butler's remote and relationship turns are scoped to a relationship. It adds the root-host tool (`sanctuary_host_execute`) in the owner's Telegram chat, and the house-care tools to the Butler's own scheduled inner turns. Its operational status (house health, policy, awaits, Telegram, events, provider lanes) is the section `query_active_work` adds. A tool can now carry its own `authorize` check, which the dispatcher runs after argument validation and before the handler. The root-host tool uses it in place of the dispatcher's special case for that one tool. On the Butler's image every turn's tool menu is the same as before, and so is every root-host call. An agent no product runs no longer gets the Butler's tool rules just because it is named `butler` or `sanctuary`. The in-turn tools X-ray loads the Butler's product, so it lists the same tools as before.
